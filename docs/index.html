RADIAL VELOCITY PRECLEANING

Two frames,
one fit

A spectrum holds two things that do not move together: the star, which shifts with the barycentric velocity, and the sky above the telescope, which does not. pca2d-preclean fits both at once and writes back spectra with the Earth's share removed, before LBL or any other code measures a velocity.

What it is, and how the pieces fit

One command reads a campaign of spectra, builds a cube, fits it, and writes corrected files that any velocity code can read. The whole chain is five stages (cube, fit, correct, figures, lbl), and each one can be run alone. Since October 2026 the same code also runs inside LBL: one PCA2D key in an LBL wrap file corrects the spectra before the velocities are measured (below).

The idea is simple enough to state in one line: over a campaign, the same wavelength sample is seen at many different barycentric velocities. Anything that keeps its place in the observer's frame while the star slides past it is not the star. Give the fit one block of components that sits still in the star's frame and another that sits still in the Earth's, and the two separate themselves.

The demonstration target throughout this page is TOI-2120, an M dwarf observed with SPIRou: 321 exposures, a wide BERV span, and deep water bands crossing the stellar lines.

The model behind it

Let \(y(\lambda, t)\) be the high-passed log flux of the exposure taken at time \(t\), sampled on a common log-wavelength grid. The model writes it as the sum of two blocks, one anchored in each frame:

\[ y(\lambda, t)\;=\;\underbrace{\bar{S}(\lambda\,\mathcal{D}_t) \;+\;\sum_{i=1}^{n_\star} a_i(t)\,P_i(\lambda\,\mathcal{D}_t)}_{\textstyle\text{the star's frame}} \;+\;\underbrace{\sum_{j=1}^{n_\oplus} b_j(t)\,Q_j(\lambda)}_{\textstyle\text{the Earth's frame}} \;+\;\varepsilon(\lambda, t) \]
  • \(\bar{S}\) is the star's mean spectrum. It carries no free amplitude: it enters with a coefficient of exactly one, so the fit can never scale the star away to explain something else.
  • \(P_i\) are the stellar variability components, \(Q_j\) the Earth components. Both are found by a weighted PCA on the cube itself, not assumed from a model atmosphere.
  • \(a_i(t)\) and \(b_j(t)\) are the only free parameters, solved one exposure at a time.
  • \(\mathcal{D}_t\) is the Doppler factor that carries the star's frame into the observer's for that exposure.

The Doppler factor is always the relativistic one, never the first-order approximation:

\[ \mathcal{D}_t \;=\; \sqrt{\frac{1 + v_t/c}{1 - v_t/c}}, \qquad v_t \;=\; v_{\mathrm{sys}} - v_{\mathrm{berv}}(t) \]

On a log-wavelength grid this is a pure translation by \(\operatorname{artanh}(v_t/c)\) divided by the grid step, which is why the grid is logarithmic in the first place. At a 30 km/s BERV the first-order form is off by \(\tfrac{1}{2}(v/c)^2 \approx\) 1.5 m/s, which is the whole scale of the measurement.

The high pass, and why it is taken against a template

Before any of this, the continuum and the blaze have to go. A Savitzky-Golay filter does that, but a filter run over a whole spectrum is dragged downward by every deep line, so the smooth curve it returns is not the continuum, it is the continuum minus a fraction of the line.

That bias would be harmless if it were the same every night. It is not. When a telluric line sweeps across the core of a stellar line with the BERV, the pixels it saturates are blanked, and the hole moves. The filter then decrouches differently from one exposure to the next, and leaves behind a residual that tracks the BERV without being stellar.

Since 2026-10-16 the high pass is therefore taken on the residual to a median template, built in the star's frame and brought back to each exposure's own frame. No line is masked, and nothing enters or leaves the mask as the BERV changes.

A bias that follows the BERV, and what removing it looks like

This is the measurement the whole method exists for. Plot each exposure's velocity residual against \(V_{\mathrm{tot}} = v_{\mathrm{rad}} - \mathrm{BERV}\), the velocity at which the star sits relative to the telluric rest frame. Near zero, every stellar line is sitting on top of the atmospheric line that contaminates it; far from zero, they have walked apart. Anything that peaks at \(V_{\mathrm{tot}} = 0\) is therefore not stellar.

A spike at \(V_{\mathrm{tot}} = 0\) that is 4.3 km/s wide is about the width of a telluric line convolved with the instrumental profile, which is what it should be if the atmosphere is what makes it. The bias amplitude and its width are strongly anticorrelated in the posterior (\(r = -0.93\)), so the two are not independently constrained: the figure beside it shows that posterior in full.

The optical spectrographs need one step the infrared ones do not: their spectra arrive with the tellurics still in them, so LBL's telluric cleaning runs first and pca2d fits the residuals of that cleaning. In the infrared, APERO has already done it.

How that cleaning is done, and the two things that had to change in it →

One trap worth stating: on HARPS the delivered wavelength grid is already barycentric, so the instrument's own BERV reads zero. Left alone, the two frames of the fit would collapse into one and the correction would make things worse: it took the rms from 11.2 to 51.6 m/s before this was caught. input.to_observer undoes the barycentric correction on the way in so that the two frames stay distinct.

Where it runs: inside LBL

The algorithm is a module of LBL, lbl.pca2d, on LBL's lbl-pca2d branch, and LBL alone runs it: no window, no other package. When the run parameters of an ordinary wrap file carry a PCA2D dict, lbl_wrap measures the object as delivered, corrects it, measures the corrected spectra as an object of their own, and writes one report. Without the key nothing of it is even imported, and LBL runs exactly as before.

from lbl.recipes import lbl_wrap rparams = dict(INSTRUMENT='NIRPS_HE', DATA_SOURCE='CADC', DATA_DIR='/data/nirps/lbl', DATA_TYPES=['SCIENCE'], OBJECT_SCIENCE=['TOI756'], OBJECT_COMPARISON=['TOI756'], OBJECT_TEFF=[3300], RUN_LBL_TEMPLATE=True, RUN_LBL_MASK=True, RUN_LBL_COMPUTE=True, RUN_LBL_COMPILE=True) rparams['PCA2D'] = dict(n_star=1, n_earth=3) # the nominal set lbl_wrap.main(rparams)

And what it leaves in LBL's tree:

DATA_DIR/science/TOI756/ read, never written DATA_DIR/science/TOI756_pca2d/ the corrected spectra, same names, same format DATA_DIR/pca2d/TOI756/1-3/ the fit, the figures, the report DATA_DIR/lblrdb/lbl_TOI756_pca2d_TOI756_pca2d.rdb the velocities DATA_DIR/reports/TOI756_pca2d_TOI756_pca2d.pdf the report

The report is the pca2d report followed by LBL's: the star as SIMBAD describes it, the delivered and corrected velocities on the exposures they share with what got better and what got worse, the river plots of the correction step by step in each window, the components, their coefficients in time and against everything they could follow, their periodograms, every setting that ran, and then LBL's series, false inclusion probabilities and indicators. A commented example wrap file, with what the precleaning does, is lbl/doc/example_wrap_pca2d.py in the branch.

With LBL's telluric cleaning on, which is the path for the optical spectrographs, the precleaning runs after it, on <object>_tc, and writes <object>_tc_pca2d. Any key of the configuration can go in the dict, by a short name (nsig_cut=0), as 'section.key' or as a dict per section; an unknown key stops the run before anything is read. name='x' keeps a variant beside the nominal as <object>_pca2d_x, and joint=True fits every object of the wrap against one observer basis. A correction already on disk with the same settings is not made again; a different one moves the previous one, and every LBL product made from it, aside rather than mixing them.

The window is only a front end to this. Same objects, same choices, same log; what it runs is that same kind of wrap file, DATA_DIR/run_<object>_pca2d.py, one dict with its PCA2D key, left there to be read and run again by hand.

Checked on SIPS J1259-4336 (NIRPS HE, 51 exposures). Through the window, the wrap file and LBL, and again from a plain wrap file with no window, the corrected velocities equal those of the standalone pipeline to 1.6×10-6 m/s, and the delivered ones are identical. The corrected flux agrees to one unit in the last place of a 32-bit float: LBL's environment does its linear algebra with Apple's Accelerate, the standalone one with a generic BLAS.
Two branches, not merged yet. main of pca2d-preclean still holds the standalone pipeline with its own copy of the engine; the version described here is on the branches below.

Install it

Two branches, one environment: LBL first, from its lbl-pca2d branch, then this package, from its lbl-wrapper branch, in the same environment.

git clone -b lbl-pca2d https://github.com/njcuk9999/lbl.git lbl-rapide conda create -n lbl-rapide python=3.12 conda activate lbl-rapide pip install -e ./lbl-rapide git clone -b lbl-wrapper https://github.com/eartigau/pca2d_preclean.git pip install -e ./pca2d_preclean

The first half alone is enough: any LBL wrap file with a PCA2D key does everything, report included, and lbl_pca2d is the command line. The second half adds the window, and no computation. LBL pins its dependencies exactly (python 3.12, numpy 2.3.3, scipy 1.17.0, astropy 7.2.0), and pip installs them with it.

Without the window: any LBL wrap file with rparams['PCA2D'] = dict(n_star=1, n_earth=3).

pca2d-gui

The window: tick the objects, choose the counts, Run. It writes the wrap file and runs it with LBL.

lbl_pca2d --object TOI2120 \ --n-star 1 --n-earth 3

The command line, for research runs side by side under their own names: the same code, lbl.pca2d. --n-star and --n-earth are how many components each block gets; everything else comes from config.yaml, and the resolved settings are written beside the outputs so a run can always be read back.

What comes out

A run leaves a folder named for the object and the component counts. Inside: the corrected spectra on their original grids, the fitted components, a CSV of every coefficient, and a PDF report of around thirty pages: the river plots above, the coefficients in time, the correlations, and, when LBL ran, the velocities and their periodograms.

LBL itself now writes a second report per run, in <DATA_DIR>/reports: a summary table with the code version it used, the velocity series, the velocities coloured by BERV, the periodogram beside the spectral window, the false inclusion probability both plain and outlier-aware, and the telluric correction on the best, median and worst exposure of the campaign.
