RADIAL VELOCITY PRECLEANING

Two frames,
one fit

A spectrum holds two things that do not move together: the star, which shifts with the barycentric velocity, and the sky above the telescope, which does not. pca2d-preclean fits both at once and writes back spectra with the Earth's share removed, before LBL or any other code measures a velocity.

What it is, and how the pieces fit

One command reads a campaign of spectra, builds a cube, fits it, and writes corrected files that any velocity code can read. The whole chain is five stages (cube, fit, correct, figures, lbl), and each one can be run alone.

The idea is simple enough to state in one line: over a campaign, the same wavelength sample is seen at many different barycentric velocities. Anything that keeps its place in the observer's frame while the star slides past it is not the star. Give the fit one block of components that sits still in the star's frame and another that sits still in the Earth's, and the two separate themselves.

The demonstration target throughout this page is TOI-2120, an M dwarf observed with SPIRou: 321 exposures, a wide BERV span, and deep water bands crossing the stellar lines.

The model behind it

Let \(y(\lambda, t)\) be the high-passed log flux of the exposure taken at time \(t\), sampled on a common log-wavelength grid. The model writes it as the sum of two blocks, one anchored in each frame:

\[ y(\lambda, t)\;=\;\underbrace{\bar{S}(\lambda\,\mathcal{D}_t) \;+\;\sum_{i=1}^{n_\star} a_i(t)\,P_i(\lambda\,\mathcal{D}_t)}_{\textstyle\text{the star's frame}} \;+\;\underbrace{\sum_{j=1}^{n_\oplus} b_j(t)\,Q_j(\lambda)}_{\textstyle\text{the Earth's frame}} \;+\;\varepsilon(\lambda, t) \]
  • \(\bar{S}\) is the star's mean spectrum. It carries no free amplitude: it enters with a coefficient of exactly one, so the fit can never scale the star away to explain something else.
  • \(P_i\) are the stellar variability components, \(Q_j\) the Earth components. Both are found by a weighted PCA on the cube itself, not assumed from a model atmosphere.
  • \(a_i(t)\) and \(b_j(t)\) are the only free parameters, solved one exposure at a time.
  • \(\mathcal{D}_t\) is the Doppler factor that carries the star's frame into the observer's for that exposure.

The Doppler factor is always the relativistic one, never the first-order approximation:

\[ \mathcal{D}_t \;=\; \sqrt{\frac{1 + v_t/c}{1 - v_t/c}}, \qquad v_t \;=\; v_{\mathrm{sys}} - v_{\mathrm{berv}}(t) \]

On a log-wavelength grid this is a pure translation by \(\operatorname{artanh}(v_t/c)\) divided by the grid step, which is why the grid is logarithmic in the first place. At a 30 km/s BERV the first-order form is off by \(\tfrac{1}{2}(v/c)^2 \approx\) 1.5 m/s, which is the whole scale of the measurement.

The high pass, and why it is taken against a template

Before any of this, the continuum and the blaze have to go. A Savitzky-Golay filter does that, but a filter run over a whole spectrum is dragged downward by every deep line, so the smooth curve it returns is not the continuum, it is the continuum minus a fraction of the line.

That bias would be harmless if it were the same every night. It is not. When a telluric line sweeps across the core of a stellar line with the BERV, the pixels it saturates are blanked, and the hole moves. The filter then decrouches differently from one exposure to the next, and leaves behind a residual that tracks the BERV without being stellar.

No line is masked, and nothing enters or leaves the mask as the BERV changes.

The optical spectrographs need one step the infrared ones do not: their spectra arrive with the tellurics still in them, so LBL's telluric cleaning runs first and pca2d fits the residuals of that cleaning. In the infrared, APERO has already done it.

How that cleaning is done, and the two things that had to change in it →

One trap worth stating: on HARPS the delivered wavelength grid is already barycentric, so the instrument's own BERV reads zero. Left alone, the two frames of the fit would collapse into one and the correction would make things worse: it took the rms from 11.2 to 51.6 m/s before this was caught. input.to_observer undoes the barycentric correction on the way in so that the two frames stay distinct.

Install it

A virtual environment keeps this separate from whatever Python the rest of your work uses, which matters because the fit pins fairly specific numpy and scipy versions.

git clone https://github.com/eartigau/pca2d_preclean.git cd pca2d_preclean python -m venv .venv source .venv/bin/activate pip install -e .

LBL is optional. Without it everything up to the corrected files still runs; with it, --stages lbl measures the velocities of both the delivered and the corrected spectra and writes the report.

Run it

pca2d --object TOI2120 \ --n-star 1 --n-earth 3 \ --stages cube,fit,correct,figures,lbl

--n-star and --n-earth are how many components each block gets. Everything else (the domain, the windows, the weights) comes from config.yaml, and the resolved settings are written beside the outputs so a run can always be read back.

What comes out

A run leaves a folder named for the object and the component counts. Inside: the corrected spectra on their original grids, the fitted components, a CSV of every coefficient, and a PDF report of around thirty pages: the river plots above, the coefficients in time, the correlations, and, when LBL ran, the velocities and their periodograms.

LBL itself now writes a second report per run, in <DATA_DIR>/reports: a summary table with the code version it used, the velocity series, the velocities coloured by BERV, the periodogram beside the spectral window, the false inclusion probability both plain and outlier-aware, and the telluric correction on the best, median and worst exposure of the campaign.
